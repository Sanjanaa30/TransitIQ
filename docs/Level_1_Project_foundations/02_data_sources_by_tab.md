## How to read the tables

The flow for every tab is **official source → small sample check → cleaned data → defined metric → website display**. “Needed?” means **selected for the project plan**, not “download it now.” A **Yes** source may still need verification before its feature goes live. **No** means it is unnecessary for the first release or its measure overlaps another source; it can be reconsidered later.

| Stage word | Meaning |
| --- | --- |
| **Verified starter** | The current monthly-source snapshot passed our first sample, coverage and numeric checks. |
| **Initial candidate** | Selected for the dashboard; some sources have a small check, but their feature rules are not yet fully verified. |
| **Conditional** | The feature appears only if a named data/method check succeeds. |
| **Later** | Forecasting, current notices or AI phase. |
| **Unsupported now** | No selected source can honestly provide that measure; hide it until evidence changes. |

Our target is **2019 through the latest published 2026 data**, but each source has its own dates. The checked monthly starter reaches **August 2026**; the checked daily source has rows through **October 29, 2026**. We never treat an incomplete 2026 year as complete.

## Common filter rule

The source must actually support a filter before that filter appears. For example, monthly ridership supports **service, year and month**; daily ridership adds **date and weekday/weekend**; hourly entries add **hour, measured complex, payment method and fare category**. LIRR occupancy supports **measured trip/stop**, while railroad fare tables support **covered origin, destination, zone and ticket type**. A monthly dataset cannot answer an hourly question. Hide unsupported filters and visuals for the selected service.

## Counting and normalization rule

The **number of source rows** tells us about coverage; it is not automatically the number of riders, incidents or trains. Before calculating each metric, Phase 4 will record its unit, numerator, denominator, eligible row count, time period and service/geography. Examples:

| Metric | Count or denominator we must use |
| --- | --- |
| Monthly ridership growth | Compare the **same service and same months** in two years; use the earlier period's ridership as the percentage denominator. |
| Average daily ridership | Divide the selected daily ridership total by **eligible observed days**, not by days with no record. |
| Distinct disruptions | Group validated alert **revisions** into events first; raw alert-row count is not incident count. |
| Reliability percentage | Use the source's eligible train trips and its stated definition; do not simply average route percentages. |
| OMNY adoption share | Divide eligible OMNY entries by eligible OMNY **plus** MetroCard entries for the **same** mode, stations and dates. |
| LIRR occupancy rate | Compare onboard load with the reported train capacity for **measured trips/stops**; disclose measurement coverage. |

We will not apply one universal “normalization factor” to every source. A rate is displayed only when its matching denominator is available and verified.
